# Grok Imagine (xAI) — 이미지·영상 프롬프트

`Grok` / `그록` / `xAI`가 지정되고 **산출물이 이미지·영상일 때** 읽는다. 대화·리서치·추출용 프롬프트는 [../model-playbooks.md](../model-playbooks.md) §Grok 텍스트·리서치를 따른다. 이름만으로 이미지 생성이나 OAuth 실행을 선택하지 않는다.

먼저 [surfaces.md](surfaces.md) §4.2에서 **Imagine UI·대화형 이미지 도구·직접 API·래퍼**를 구분한다. 여기서는 그 표면에 보낼 자연어만 작성한다. 실행·참조 업로드·장수 처리는 [../adapters.md](../adapters.md)의 현재 실행 어댑터 소관이다. 공식 근거·확인일은 [surfaces.md](surfaces.md) §7에 있다.

## 게이트 카드

| 항목 | 규칙 |
|---|---|
| 네거티브 | 원하는 결과 상태를 우선 쓰고 필요한 변경·보존·추가 금지는 짧게 명시. MJ/SD 스타일 `--no` 스택 금지 |
| 비율 | `--ar` / 끝 `AR x:y` 형식은 쓰지 않는다. 설정과 자연어의 분기는 [surfaces.md](surfaces.md) §4.2를 따른다 |
| 길이 | [surfaces.md](surfaces.md) §0-1·§0-2의 실제 상한과 가장 짧은 완결본 기준. 최소·목표 분량 없음 |
| 필수 | 요청한 피사체·행동/편집·보존·출력 조건. 사진 오프너·렌즈·빛·매체는 해당 표현이 필요할 때만 선택 |
| 금지 플래그 | Midjourney `--p` / `--stylize` / `--v` / `--sref` / `--seed`, SD weight `::`, 로컬 경로 참조 |

이 카드는 Grok 자연어 작성 정책이다. 기본 `check_prompt.mjs`의 MPW `compiled` 형식이나 GPT Image 전용 `native` 프로필이 Grok 검증을 대신하지 않는다. 길이·입력 역할·표면별 설정을 별도로 확인하며 문서 검사 통과를 실제 생성 품질로 보고하지 않는다.

## 이미지 — 필요한 조건부터

짧은 자연어와 사용자 지정 언어를 유지한다. 아래는 MPW 작성 정책이며 최소 분량이나 모델의 성능 보증이 아니다.

| 작업 | 남길 정보 |
|---|---|
| 새 이미지 | 무엇을 어떤 매체로 보여줄지 → 피사체의 행동·구도 → 결과를 가르는 빛·색·재질. 렌즈·필름·외형 슬롯은 필요할 때만 |
| 편집 | 바꿀 대상과 변화, 유지할 부분. 전체 장면을 다시 설계하지 않고 원본 로고·글자 보존에 `brand-free`를 추가하지 않음 |
| 여러 이미지 합성 | 입력 순서에 따라 `첫 이미지의 인물, 둘째 이미지의 의상`처럼 역할을 연결. 구도 기준·보존 대상과 가져오지 않을 요소가 중요하면 명시 |
| 포스터·문자 | 정확 문구·표기 언어·배치와 정보 위계. 텍스트가 필요한 요청에 임의로 무문자 조건을 넣지 않음. [typography.md](typography.md)의 정확 카피 계약 적용 |

입력 역할과 원본 보존은 [from-image.md](from-image.md)·[compiler.md](compiler.md) 철칙 8을 따른다. 반복 편집은 선택한 직전 결과를 실제 입력이나 대화 상태로 연결한다. `아까 사진`이라는 문장만으로 직접 API가 이미지를 기억한다고 가정하지 않는다. 원본에서 새 변형을 만드는 요청은 직전 결과 대신 원본을 사용한다.

편집 예시 — 첨부한 제품 사진의 배경만 교체:

```text
첨부한 제품 사진의 배경만 따뜻한 회색으로 바꾼다. 제품의 모양·원래 색·재질·로고·그림자와 화면 안 위치·크기는 유지한다.
```

## 영상 — 입력 역할에 맞는 변화

공통 영상 규칙은 [lanes.md](lanes.md) §영상 공통 규칙을 따른다. 장면·행동·카메라·분위기 중 필요한 것을 쓰고, 시간 순서가 중요할 때 시작 → 변화 → 끝 상태를 연결한다. 정지 카메라를 요청했으면 팬·줌·오빗을 추가하지 않는다.

| 입력 모드 | 프롬프트의 중심 |
|---|---|
| 텍스트 → 영상 | 보일 장면과 일어날 행동, 필요한 카메라 움직임·페이스 |
| 이미지 → 영상 | 시작 이미지에서 무엇이 어떻게 움직일지, 중요한 보존 조건. 이미 보이는 외형 전체를 반복하지 않음 |
| 참조 → 영상 | 실제 연결한 이미지·음성의 역할, 새 장면·행동. 참조 이미지를 첫 프레임으로 고정하는 지시와 혼동하지 않음 |
| 영상 편집 | 원본에서 바꿀 부분과 유지할 동작·카메라·배경 |
| 영상 연장 | 마지막 프레임에서 다음에 일어날 행동과 끝 상태. 완성된 앞부분을 다시 서술하지 않음 |

대사·언어·화자와 효과음은 요청에 있을 때 구분해 쓴다. 목소리 선택·참조 태그·모드 조합은 [surfaces.md](surfaces.md) §4.2의 실제 입력 계약을 먼저 확인한다. 문장에 파일명이나 태그를 적는 것으로 입력 첨부를 대신하지 않는다.

이미지 → 영상 예시 — 첨부한 인물 사진을 시작 프레임으로 연결:

```text
인물이 컵을 들어 한 모금 마신 뒤 천천히 내려놓는다. 카메라는 고정한다. 얼굴·의상·배경과 원래 조명을 유지한다.
```

## 타엔진에서 옮길 때

| 가져오지 말 것 | 대신 |
|---|---|
| 끝 `AR 3:4` | 실제 설정으로 분리하거나, 설정 없는 대화형 도구라면 자연어로 요청(표면 계약 참조) |
| `--p m…` personalization | 생략. 얼굴은 기하 코어 또는 이미지 참조 슬롯 |
| 요청에 없는 HEX 묶음 | 필요한 색 이름이나 원본 색 보존 지시 |
| Higgsfield 프리셋명 본문 삽입 | UI 프리셋 분리 |
| 긴 헤더형 Scene/Camera 라벨 블록 | 한 문단 산문 |

## 요청 분기

| 사용자 말 | 산출 |
|---|---|
| `그록용으로 다시` | 직전 산출물 종류·표면을 유지해 프롬프트만 변환 |
| `Grok Imagine 프롬프트` | 이미지·영상 프롬프트 작성. 실제 생성은 실행 요청이 있을 때만 |
| `Grok/그록/xAI로 생성` + 장수·클립 수 | 현재 설치된 실행 어댑터의 해당 표면으로 인계. 이름만으로 특정 OAuth·래퍼를 강제하지 않음 |
| NSFW·란제리·시어 패션 | 성인 가상 페르소나 + 화면 서술 (`lingerie-editorial, adult, no explicit genitals, no sex act`) |

## 출력 형식

- 복사 블록 1개 = 독립적으로 실행할 이미지 요청·클립. 한 이미지 안의 다중 패널은 한 요청을 유지한다.
- 변형 컷은 별 블록. 비교 실험은 한 축씩, 사용자가 여러 축을 지정하면 그 범위를 보존한다.
- `길이: N자`는 실측만
- 실행 요청이 없으면 프롬프트만 반환

## 함정

- Grok용인데 MJ 플래그를 본문에 남기면 무시되거나 노이즈.
- “xAI 느낌”만으로는 제공자 라우트가 아님 — 미학과 `Grok으로 생성` 실행 의도를 혼동하지 않는다.
- 참조가 필요한 신원 보존은 해당 표면의 실제 입력 지원을 확인한다. 불명확한 지원을 텍스트 외형 묘사만으로 보장하지 않는다.
- 지원되지 않는 비율·품질·참조 모드를 프롬프트 문장으로 해결했다고 보고하지 않는다.
- 프롬프트 재작성 요청에 ImgGen2/`image_generate`를 끼워 넣지 말 것.
