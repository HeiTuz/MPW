# Nano Banana (Google Gemini 이미지) — 이미지 프롬프트

`Nano Banana` / `나노바나나` / `Gemini 이미지`가 지정되고 산출물이 이미지일 때 읽는다. 대상이 정해지지 않았으면 이 파일이 아니라 기본 경로인 [gpt-image-2-5.md](gpt-image-2-5.md)를 따른다. 공식 근거와 확인일은 [surface-evidence.md](surface-evidence.md) §7에 있다. 실행·참조 업로드는 현재 실행 어댑터 소관이다.

## 모델

사용자가 모델을 지정하지 않았으면 모델을 고르라고 묻지 않고 Nano Banana 2 기준으로 쓴다. 모델 이름·ID와 고르는 기준은 [model-routing.md](model-routing.md) §6, 비율·해상도·출력 형식 같은 실행 설정은 [surfaces.md](surfaces.md)와 선택한 표면의 호출 계약이 맡는다. 이 파일은 프롬프트 문장만 다룬다. 본문에 `--ar`이나 `AR x:y`를 붙이지 않는다.

## 작성 구조

키워드 나열이 아니라 장면을 서술하는 문장으로 쓴다. 첫 문장은 만들 작업을 드러내는 동사로 시작한다(만들어 줘, 바꿔 줘, 합쳐 줘). 결과에 필요한 칸만 쓰고 순서는 아래를 따른다.

- **참조 없는 생성:** 피사체 → 동작 → 장소·맥락 → 구도 → 스타일.
- **참조가 있는 생성:** 참조 이미지마다 역할(구조, 질감, 인물, 제품, 배경 등)을 붙이고 → 참조끼리의 관계 → 새 장면. 예: 첫 번째 이미지의 스케치를 형태로, 두 번째 이미지의 원단을 질감으로 써서 새 장면을 만든다.
- **용도:** 무엇에 쓸 이미지인지 한 줄로 밝힌다. 공식 안내는 맥락과 의도가 결과에 영향을 준다고 설명한다.
- **복잡한 장면:** 배경 → 중간 → 전경처럼 단계로 나눠 쓴다.
- **원하는 상태로:** 빼고 싶은 것을 부정문으로 쓰지 않고 원하는 상태를 쓴다. 예: 차가 없는 거리 대신 텅 빈 거리.

## 편집

원본 편집의 공통 규칙(바꿀 것과 유지할 것, 보존 대상 명시)은 [compiler.md](compiler.md)와 참조 역할 판정 [from-image.md](from-image.md) §1을 따른다. Google 안내에서 이 엔진에 고유한 부분은 둘이다. 특정 부분만 바꿀 때 그 대상을 문장으로 지정하는 시맨틱 마스킹, 그리고 처음부터 다시 생성하기보다 같은 대화에서 한 가지씩 고치는 방식이다.

## 이미지 안의 글자

정확 카피와 글자 배치는 [text-structure.md](text-structure.md) §이미지 안의 글자를 따른다. Google 안내에서 이 엔진에 고유한 부분은, 문구를 먼저 대화로 확정한 뒤 그 문구로 이미지를 요청하면 가장 잘 된다는 점과, 프롬프트는 한 언어로 쓰고 렌더할 대상 언어를 따로 지정할 수 있다는 점이다.

## 카메라·렌즈 용어 — 엔진 예외

MPW 기본은 장비·수치를 화면 결과로 바꿔 쓰는 것이다([compiler.md](compiler.md) §결과로 쓴다). Nano Banana는 공식 안내가 앵글·렌즈·조리개·카메라 종류·필름 질감 같은 촬영 용어를 제어 수단으로 직접 권한다. 그래서 이 엔진에서는 사용자가 그 룩을 원하거나 결과를 가르는 경우에 촬영 용어를 남길 수 있다. 이때도 용어 하나에 보이는 결과를 붙인다(예: 낮은 앵글, 얕은 심도로 배경이 녹는다). 요청에 없는 장비명을 기본값으로 채우지 않는다.

## 참조 이미지

참조마다 역할을 붙인다(위 §작성 구조). 모델마다 잘 처리하는 참조 수가 다르므로 장수는 [surface-evidence.md](surface-evidence.md) §7의 Nano Banana 행과 실행 표면에서 확인한다. 같은 캐릭터의 여러 각도는 앞서 생성한 이미지를 다음 요청에 함께 넣는다.

## 한계 — 프롬프트로 약속하지 않는 것

- 요청한 출력 장수를 정확히 따르지 않을 수 있다. 장수가 중요하면 실행 쪽에서 세고 다시 요청한다.
- 권장 언어 목록에 한국어(ko-KR)가 있다. 그 밖의 언어는 결과가 떨어질 수 있다.
- Nano Banana 2의 이미지 검색 그라운딩은 실존 인물 이미지를 쓰지 않는다.
- 모든 결과에 SynthID 워터마크가 들어간다. 워터마크 제거를 프롬프트로 요구하지 않는다.
- 작은 글자, 철자, 도표의 사실관계는 생성 뒤 확인한다.

## 다른 엔진과 오갈 때

옮겨 갈 엔진의 규칙을 따른다. 사용자가 명시한 장비·매체·렌즈 요구는 엔진이 바뀌어도 보존한다. 다른 엔진에서 들어올 때는 Midjourney 파라미터(`--ar` `--v` `--sref` `--stylize` `--no`)와 가중치 문법을 지우고 같은 뜻을 문장과 호출 설정으로 옮긴다. Soul의 용어 스택은 문장으로 풀어 쓴다.
