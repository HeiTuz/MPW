# Midjourney — 파라미터 정본과 인물 정체성 경로

타깃 엔진이 Midjourney일 때 이 파일을 먼저 읽는다. 문법·파라미터·레퍼런스 슬롯·무드보드 경로의 정본이다. 캐릭터 시트·턴어라운드의 산문 규칙은 [midjourney-character-sheets.md](midjourney-character-sheets.md)가 갖는다.

표면 판정(기계 계약 / 플랫폼 파라미터 / 붙여넣기 UI)과 거기서 나오는 길이·비율 소관은 [image/surfaces.md](image/surfaces.md)가 정본이다. 이 파일은 **타깃 엔진 층의 제약**만 적는다.

버전·참조·편집 경로는 **2026-09-05 공식 문서 확인** 기준이다. 기능별 문서와 호환표가 충돌하면 현재 선택 모델·웹/Discord 표면을 확인한다. 오래된 미지원 설명만으로 기능을 막거나 모델을 바꾸지 않는다.

## 1. 버전 기준선

- 현행 기본 모델은 **V8.2**(2026-07-24 적용). 이 문서의 V8 계열은 V8.1·V8.2다. 사용자가 V7 등 특정 버전을 정했으면 유지한다. 기본값·기능 차이는 [Version](https://docs.midjourney.com/hc/en-us/articles/32199405667853-Version)에서 확인한다.
- V8 계열에는 **Edit Model**이 있다. 레퍼런스 인물·사물 재사용과 편집에 이 경로를 쓰며, `--oref`가 없다는 이유로 동일성 요구를 포기하지 않는다.
- Version 표상 V8 계열은 `--q`, `--turbo`, `--niji`, 일반 `::` 멀티프롬프트를 지원하지 않는다. V8.1·V8.2를 묶은 표로부터 표 밖의 모든 파라미터 값역까지 같다고 추정하지 않는다.

레퍼런스 축 호환:

| 축 | V6 | V7 | V8 계열 (8.1·8.2) |
|---|---|---|---|
| Image Prompt / `--iw` | O | O | O |
| Style Reference `--sref` · 스타일 코드 · `--sw` | O | O | O |
| Moodboard·Personalization `--p` | O | O | O |
| Character Reference `--cref` / `--cw` | O | X | X |

| `--exp` | X | O | O |

## 2. 인물 정체성과 편집 경로

- **V8 계열:** Edit Model에 원본·레퍼런스를 연결한다. 웹에서는 **Attach to prompt**, Discord에서는 뒤쪽 파라미터 구간의 **`--edit URL1 URL2`**를 쓴다. 최대 4장이고 방향 전환·여러 참조 결합·부분 편집을 지원한다. 비율은 첫 이미지에서 가져오므로 변경할 때 `--ar`를 명시한다. `--tile`과 Edit 결과의 Remix는 현재 비호환이다. [Edit Model](https://docs.midjourney.com/hc/en-us/articles/48495453462797-Edit-Model)
- **V7 지정:** Omni Reference 1장과 `--oref URL`을 유지한다. `--ow`는 필요할 때만 조절한다. V8 편집 문법을 V7에 섞지 않는다. 편집·모드 조합의 지원 여부는 [Omni Reference](https://docs.midjourney.com/hc/en-us/articles/36285124473997-Omni-Reference)를 확인한다.
- **V6·Niji6 지정:** 기존 Character Reference 경로다. `--cref`·`--cw`를 V8용 문법으로 번역 없이 넘기지 않는다. [Legacy Features](https://docs.midjourney.com/hc/en-us/articles/33329788681101-Legacy-Features)

Edit 프롬프트는 **참조별 역할 → 바꿀 부분 → 보존 조건**만 짧게 쓴다. 예: “첫 이미지의 인물을 두 번째 이미지의 코트로 바꿔 입힌다. 얼굴·머리·포즈·배경은 유지한다.” 참조에 이미 보이는 얼굴·의상을 장문으로 다시 열거하지 않는다. 실제 참조가 없는데 동일인물을 요구하면 그 이미지를 요청하며 URL·얼굴 특징을 지어내지 않는다.

동일성·로고·정확 문구·원본 픽셀의 보존 요구는 유지하고, 결과를 원본과 비교한다. 참조 연결이나 보존 문구만으로 완전한 복제·픽셀 동일성이 보장된다고 쓰지 않는다. 엄밀한 픽셀 보존 작업은 편집 영역·마스크와 산출물 대조까지 확인한다.

## 3. 필요한 파라미터만 선택한다

| 파라미터 | 범위 / 기본값 | 비고 |
|---|---|---|
| `--ar` | 정수:정수, 소수점 불가 | 사용자 비율 유지. 예: `139:100`. Edit의 비율 출처는 §2. [Aspect Ratio](https://docs.midjourney.com/hc/en-us/articles/31894244298125-Aspect-Ratio) |
| `--raw` | 선택적 사용 | 자동 스타일 개입을 줄일 때 쓴다. 모든 요청에 붙이지 않는다. [Raw](https://docs.midjourney.com/hc/en-us/articles/32634113811853-Raw) |
| `--seed` | 정수 0–4294967295 | 통제 비교용이며 다른 프롬프트의 동일 인물·스타일을 저장하는 수단이 아니다. [Seeds](https://docs.midjourney.com/hc/en-us/articles/32604356340877-Seeds) |
| `--iw` | V8.1·V7 0–3 / 기본 1; Niji7 0–2 | V8.2 지원은 Version 표에 있지만 값역 표는 V8.1까지다. 필요하면 현재 입력 표면에서 확인한다. [Image Prompts](https://docs.midjourney.com/hc/en-us/articles/32040250122381-Image-Prompts) |
| `--sw` | 0–1000 / 100 | Style Reference 강도. 무드보드와 비호환. §6 참조 |
| `--ow` | 1–1000 / 100 | V7 Omni 전용. §2 참조 |
| `--s` (`--stylize`) | 0–1000 / 100 | 무드보드 강도에도 작용. §7 참조 |
| `--c`, `--w`, `--exp`, `--hd`, `--sd` | 현재 모델·UI에서 확인 | 요청한 결과에 필요한 값만 추가한다. 구버전 권장 대역·비용을 최신 모델의 기본값으로 복사하지 않는다 |
| `--sv` | V7 1–6 / 6; V6 1–4 / 4 | V8 전용 값역은 **[미확인]**. 버전별 확인 없이 V7 값을 자동 추가하지 않는다. §6 참조 |
| `--repeat` (`--r`) | 현재 플랜·모드별 확인 | 같은 프롬프트를 반복 실행하는 옵션. 각도 시퀀스가 아니며 재실행할 때 다시 넣어야 한다. [Repeat](https://docs.midjourney.com/hc/en-us/articles/32757107922061-Repeat) |

## 4. 표기 규칙

- 파라미터는 **항상 프롬프트 텍스트 뒤**에 온다. 텍스트와 `--` 사이에 공백 1개, `--`와 이름 사이에는 공백을 넣지 않는다. 파라미터 뒤에 텍스트를 다시 붙이지 않는다.
- 파라미터 값 뒤에 문장용 쉼표·마침표를 덧붙이지 않는다. URL·버전값 내부의 문자, `--no` 값 나열, permutation `{}` 문법은 보존한다.
- **ASCII 이중 하이픈 `--`만 허용한다.** U+2013 en dash와 U+2014 em dash는 모양이 비슷해도 파라미터가 아니므로 출력 전에 잡아 교정한다.
- permutation·repeat는 요청된 배치에만 사용하며, 실행 전 현재 플랜·모드 조합을 확인한다. 한 장 요청에 탐색용 배치를 자동으로 붙이지 않는다.
- `--repeat`은 한 각도의 변형을 만들 뿐, 통제된 다각도 세트를 만들지 않는다.

## 5. 배제와 보존

일반 Imagine 프롬프트는 원하는 장면을 긍정형으로 쓰고, 필요한 배제만 `--no`에 짧은 명사로 둔다. `--no`는 각 단어를 따로 읽으므로 “modern clothing”처럼 의미가 갈리면 원하는 의상을 본문에 직접 적는다. 일반 본문에 `red::-0.5` 같은 멀티프롬프트 문법을 만들지 않는다. [No](https://docs.midjourney.com/hc/en-us/articles/32173351982093-No)

**Edit Model에는 §2의 변경·보존 지시를 허용한다.** “로고를 추가하지 않는다”를 `--no logos`로 바꿔 원본 로고까지 제거하는 식으로 의미를 넓히지 않는다. `--no`를 쓸 경우 다른 파라미터와 같은 산출 블록에 둔다.

## 6. 레퍼런스 슬롯과 프롬프트 문체

| 슬롯 | 문법 | 가져오는 것 | 가중치 |
|---|---|---|---|
| Image Prompt | Discord는 URL을 **프롬프트 맨 앞**에, 여러 장은 공백 구분 | **내용·구도·색** | `--iw` |
| Style Reference | `--sref <URL 또는 코드>`, 공백 구분 다중, URL+코드 혼용 가능 | **감도만** — 색·매체·질감·조명 | `--sw` |
| Edit Model Reference | 웹 Attach to prompt / Discord `--edit URL1 URL2`, 최대 4장 | 원본 편집·참조 인물/사물·요소 결합 | 확인되지 않은 전용 가중치를 만들지 않는다 |
| Omni Reference | `--oref <URL>`, **1장만** (V7) | 인물·사물의 **동일성** | `--ow` |
| Starting Frame | 영상용 | 첫 프레임 | — |

- **일반 Image Prompt:** 최종 화면에 보여야 할 내용을 묘사한다. 원본의 정확 복제 기능으로 취급하지 않는다. **Edit:** §2처럼 변경 지시를 쓴다. 일반 Image Prompt의 문체를 Edit에 일괄 강제하지 않는다. [Image Prompts](https://docs.midjourney.com/hc/en-us/articles/32040250122381-Image-Prompts)
- **Style Reference:** 스타일 전달용이다. 내용 보존이 필요한 이미지를 단순히 sref로 옮기지 않는다. 감도만 원하는데 내용이 섞이면 먼저 실제 슬롯을 확인하고, 필요하면 스타일 영향도 또는 참조 한 축만 조정한다. 얼굴·의상 금지어를 늘려 해결하지 않는다.
- 스타일 본문은 짧게 유지한다. 맞지 않는 스타일어를 제거하고 필요한 묘사만 보강한다. 업로드 이미지에서 sref 코드를 추출한다고 주장하지 않는다. `--sv`의 문서화된 버전 범위와 구형 코드 재현은 현재 [Style Reference](https://docs.midjourney.com/hc/en-us/articles/32180011136653-Style-Reference)를 따른다.
- Discord의 개별 스타일 참조 가중치는 `--sref URL1::2 URL2::1`로 문서화되어 있다. 일반 본문의 `::` 멀티프롬프트와 구분하며, 사용할 모델 버전에서의 지원은 현재 표면으로 확인한다.

## 7. 무드보드 경로

무드보드는 Personalization 경로인 **`--p`**로 참조한다. 특정 보드는 `--p mID`, 과거 버전 재현은 `--p code`를 쓴다. 보드 ID는 제출할 때 스냅샷 코드로 바뀐다. **`--sw`·`--sv`와 비호환**이며 강도는 `--stylize`로 조절한다. [Moodboards](https://docs.midjourney.com/hc/en-us/articles/39193335040013-Moodboards)

- 프로젝트 룩이 승인되면 모델 버전과 실제 스냅샷 코드를 함께 기록한다. 보드 구성이 바뀌어도 승인한 기준을 비교할 수 있게 한다.
- 특정 장수·프로필 스택·stylize 대역을 보편 기본값으로 넣지 않는다. 실제 실패가 있을 때 해당 참조의 영향만 분리해 확인한다.
- 사용자 계정에 묶인 프로필·스타일 코드는 해당 실행에서 제공된 값만 쓰고 공용 템플릿에 복제하지 않는다.

### `--sref random` + Draft 샘플러

- `--sref random`은 제출 후 코드가 되고, reroll·variation에서는 유지된다. 채택한 코드만 후속 프롬프트에 고정한다. V7용 `--sv` 제약을 V8 전체의 지원 여부로 확대하지 않는다. §6의 Style Reference 문서 참조.
- **Draft 지원은 공식 문서가 불일치한다.** Version 표는 V8 계열을 미지원으로 표시하지만, [Draft & Conversational Modes](https://docs.midjourney.com/hc/en-us/articles/35577175650957-Draft-Conversational-Modes)는 V8.1·V8.2의 웹 전용 Draft 동작을 설명한다(2026-09-05). 실행할 웹 UI와 선택 모델에서 확인하며, 무조건 미지원으로 막거나 Discord 지원으로 확대하지 않는다.
- 샘플러는 탐색 요청에만 쓴다. 현재 출력 수·모드·비용을 확인하고, 한 장 요청을 임의로 다수 잡으로 바꾸지 않는다. 문서화되지 않은 `--preview`를 자동으로 넣지 않는다.

## 8. 짧은 완결본

길이·간결성 정본은 [image/surfaces.md](image/surfaces.md) §0-1·§0-2다. 단어 수로 채널의 문자 제한을 대체하지 않는다. 핵심 피사체·수량·요청 구도·정확 문구·보존 조건은 남기고 반복 묘사를 줄인다. 렌즈·조명·얼굴 지오메트리는 요청이나 실제 오류 교정에 필요할 때만 넣는다.

- 붙여넣기 산출은 **한 블록**이다. 일반 Image Prompt URL은 앞, `--edit`·`--oref`·`--sref` URL은 해당 뒤쪽 파라미터의 값이다. 모든 참조 URL을 앞으로 옮기지 않는다.
- 웹 업로드는 실제 연결된 슬롯과 이미지 순서를 짧게 안내한다. 파일·URL이 없는 참조를 있는 것처럼 쓰거나 가짜 링크를 채우지 않는다.
- 한 캔버스의 여러 뷰는 한 프롬프트다. 사용자가 독립 컷을 요청한 경우에만 컷별 블록을 낸다.

## 9. Identity prompt core

실제 인물 참조를 연결하고 보존할 특징만 이름으로 부른다. 예: 얼굴 윤곽·눈 간격·헤어라인. 사용자 지정 인물·의상·표정·프레이밍을 유지하고, 참조에 없는 국적·신장·신체 비율을 추정하지 않는다. 얼굴 비교가 목적일 때만 중립 표정과 일정한 프레이밍을 사용한다.

## 10. Identity delta 워크플로

- 사용자가 요청한 변경 축을 적용하며, 승인된 원본·스타일 기준과 수정본을 비교한다. 여러 변경이 요청됐다는 이유만으로 불필요한 중간 잡을 만들지 않는다.
- 드리프트 원인을 찾는 재시도는 한 축씩 비교한다. 추가 금지어를 쌓기 전에 직전 승인 컷·실제 참조 연결·변경 구간을 확인한다.
- 다중 인물은 참조별 인물과 역할을 명확히 한다. 특징이 섞이면 역할 문장을 고치거나 승인된 통합 참조를 검토한다. 사용자에게 제공받지 않은 인물을 합성해 참조를 대신하지 않는다.

## 11. 출력 레이아웃과 각도 시퀀스

- 사용자 지정 뷰 수·순서·캔버스 수·비율을 우선한다. 전신 시트는 머리부터 발끝까지 보이도록 한 번 명시한다.
- V8 Edit는 관점 변경을 지원하므로 같은 원본을 바탕으로 요청 각도를 지시할 수 있다. V7 요청은 §2의 Omni 경로를 유지한다.
- 한 시트의 뷰가 흔들리면 먼저 해당 레이아웃·참조 연결을 수정한다. 독립 잡이 필요한 경우 이유를 밝히며, 한 장 요청을 고정 10컷 배치로 바꾸지 않는다.
