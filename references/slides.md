# 슬라이드·발표 덱 — 아웃라인 선행 계약

슬라이드 덱은 컷 프롬프트를 쓰기 전에 아웃라인이 확정돼야 한다. 아웃라인 없이 만든 덱은 컷마다 다른 논지를 갖는다. 아웃라인은 모든 컷 산출물의 공통 `requires` 조상이다.

## 메시지 계층화 3요소

- 핵심 메시지 1문장
- 지지 포인트 3–5개 (생성 순서가 아니라 청중 관련성 순)
- CTA(행동 유도) 1개

## 청중 결정 매트릭스

| 질문 | 내용 |
|---|---|
| 주요 청중 | 의사결정권자 / 영향자 / 최종 사용자 |
| 현재 믿는 것 | 청중의 기존 신념·우려 |
| 원하는 결정 | 이 발표 후 취해야 할 행동 |
| 장벽 | 행동을 가로막는 이의제기·비용·위험 |
| 설득 증거 | 장벽을 깨뜨릴 구체적 사실·데이터 |

## 콘텐츠 유형과 시각화 형식

컨텐츠가 무엇인지에 따라 적합한 시각화를 선택한다.

| 콘텐츠 | 시각화 형식 |
|---|---|
| 비교 | 나란한 막대·점 차트 또는 표 |
| 프로세스·순서 | 화살표 흐름도 또는 타임라인 |
| 계층·분해 | 트리맵·썬버스트 또는 아웃라인 표 |
| 시간 변화 | 선 그래프 또는 영역 차트 |
| 통계·합계 | 원형 차트·히스토그램 또는 게이지 |
| 개념·관계 | 다이어그램·마인드맵 또는 네트워크 |

## 아웃라인 표 스키마

아웃라인은 다음 컬럼으로 잠근다.

| # | 유형 | 헤드라인 | 핵심 내용 | 시각 요소 | 레이아웃 |
|---|---|---|---|---|---|

타입: 커버 / 컨텍스트 / 콘텐츠 / 마무리 / 클로징 중 하나. 각 슬라이드는 메시지 1개만 갖는다.

## 발표 흐름 패턴 5종

어느 흐름을 선택해도 되지만 섞지 말고 하나로 일관성 있게 진행한다.

1. **문제→해결**: 현재 상황 → 문제 정의 → 제안 솔루션
2. **상황→복잡화→해결**: 배경 → 문제 심화 → 해결책
3. **What→Why→How**: 무엇인가 → 왜 중요한가 → 어떻게 실행하는가
4. **과거→현재→미래**: 지금까지 → 현재 상황 → 앞으로의 방향
5. **주장→근거→시사점**: 주요 발견 → 근거 데이터 → 권고사항

## 컷 규칙 3개

- **메시지 1개**: 슬라이드당 핵심 메시지는 1개만. 여러 주장은 여러 슬라이드로 분산한다.
- **자체 완결**: 구두 설명 없이 슬라이드 텍스트와 그래픽만으로 의도가 전달돼야 한다.
- **텍스트 비중 계층**: 데이터 슬라이드(최소) < 콘텐츠 슬라이드 < 문맥 슬라이드 < 마무리 슬라이드 < 커버/클로징 슬라이드(최대). 백분율이 아니라 상대 서열이다.

## `feeds` 계약 — 아웃라인에서 컷별 이미지까지

아웃라인 테이블이 다음 단계 입력이 될 때, payload는 다음을 포함한다:

- **형식 명칭과 버전**: 어떤 스키마인가 (`outline/v1` 등)
- **넘어갈 것**: 각 행의 (유형 / 헤드라인 / 핵심 내용 / 시각 요소)
- **안 넘어갈 것**: 레이아웃은 다음 단계에서 재판정한다
- **보존할 provenance**: 원본 아웃라인의 출처·버전·체크섬 기록 (동일성 검증용)

수신 단계는 payload 정본을 보고 자신의 판정법([contracts.md](contracts.md) 참조)을 먼저 확인한 뒤 프롬프트를 생성한다.

## 완료 체크리스트

- [ ] 아웃라인이 확정되고 메시지 계층화가 완료되었는가
- [ ] 각 컷이 메시지 1개를 정확히 전달하는가
- [ ] 구두 설명 없이 슬라이드만으로 논지가 따라가는가
- [ ] 컷 간 흐름 패턴이 일관되는가
