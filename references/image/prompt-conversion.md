# 이미지·영상 프롬프트의 엔진 간 변환

기존 이미지·영상 프롬프트를 다른 엔진·표면용으로 옮기는 요청("미드저니용으로 바꿔줘", "이걸 Nano Banana에 맞게", "Seedance 프롬프트로")에 적용한다. 텍스트 모델 간 변환은 [../model-playbooks.md](../model-playbooks.md) §공통 적응 규칙, 생성된 이미지에서 프롬프트를 복원하는 일은 [from-image.md](from-image.md) §4 소관이다. 각 엔진의 문법·파라미터는 [model-routing.md](model-routing.md) §6의 어댑터와 [surfaces.md](surfaces.md)가 정본이며 이 파일은 옮기는 절차만 정한다.

## 1. 기준과 대상 확정

- **기준 원문:** 변환할 프롬프트를 [../templates/common.md](../templates/common.md) §기준 원문과 누적 수정 1단계대로 실제로 확보한다. 대화에 여러 문안이 있으면 요청이 가리키는 문안을 쓴다.
- **대상:** 엔진과 표면을 함께 정한다. 같은 엔진도 표면이 다르면 계약이 다르다([surfaces.md](surfaces.md) §0). 버전·표면이 언급되지 않았으면 해당 어댑터의 기본 경로를 쓰고 그 가정을 블록 밖에 한 줄로 밝힌다. 변환을 이유로 엔진·버전 선택을 따로 묻지 않는다.
- 대상 어댑터는 그 엔진의 해당 입력 모드 절만 읽는다. 원본 엔진의 문서는 원문에서 엔진 전용 문법을 가려내는 데 필요할 때만 연다.

## 2. 내용과 엔진 문법을 나눈다

원문을 두 층으로 나눈다.

| 층 | 예 | 처리 |
|---|---|---|
| **내용** — 결과를 정한다 | 피사체·행동·관계, 장면·빛·구도, 정확 카피·대사, 입력 역할, 변경·보존 조건, 비율·길이 같은 사용자 요구, 수량 | 모두 보존한다. 표현 방식만 대상 엔진에 맞춘다 |
| **엔진 문법** — 원 엔진에서만 뜻이 있다 | `--` 플래그·가중치·`--no`, 참조 번호 표기(`@Image N`·`<IMAGE_1>` 등), 좌표·라벨 섹션·타임코드 양식, 고정 헤딩·필드명, 엔진 고유 프리셋·스타일 코드 | 대상 엔진에서 같은 결과를 내는 수단으로 바꾸거나, 대응이 없으면 뺀다 |

원문에 섞인 품질 태그·장비명처럼 결과를 말하지 않는 표현은 대상 엔진 어댑터가 허용할 때만 남기고, 그 외에는 화면 결과로 바꾼다([compiler.md](compiler.md) §결과로 쓴다).

## 3. 대상 엔진에 맞춰 다시 조립한다

- **파라미터:** 비율·해상도·길이·시드·스타일 강도는 대상 표면의 실제 전달 수단(플래그·API 필드·UI 설정)으로 옮긴다([surface-contracts.md](surface-contracts.md) §4). 대상이 지원하지 않는 값은 가까운 값으로 몰래 바꾸지 않는다. 사용자 요구였던 값이면 블록 밖에 차이를 알리고, 지원값 중 하나를 골라야 결과가 성립할 때만 그 선택을 묻는다.
- **배제:** 원문의 제외 지시는 대상 표면 형식으로 옮긴다. 인라인 배제 문법·별도 필드가 있으면 그것을, 없으면 원하는 상태의 서술로 바꾼다([surface-contracts.md](surface-contracts.md) §4).
- **참조:** 입력 이미지·영상의 역할을 대상 엔진의 참조 슬롯·표기로 다시 연결한다. 슬롯 수나 역할 종류가 달라 연결할 수 없으면 무엇이 빠지는지 알리고, 원문 표기를 그대로 남기지 않는다.
- **구조와 길이:** 대상 어댑터의 작성 구조를 따른다. 원문의 헤딩·섹션·문단 배치는 대상이 요구하거나 허용할 때만 유지한다. 길이는 [surfaces.md](surfaces.md) §0-1·§0-2로 다시 판정하며, 원문 길이를 기준으로 삼지 않는다.
- **언어:** [../templates/common.md](../templates/common.md) §프롬프트 언어 결정을 따른다. 대상 엔진의 입력 언어 제약이 있으면 정확 카피·대사는 원문 그대로 두고 나머지만 옮긴다.
- **추가하지 않는다:** 변환은 내용을 새로 연출하는 작업이 아니다. 원문에 없던 장면·빛·스타일·네거티브를 덧붙이지 않는다. 대상 엔진이 결과를 내려면 꼭 필요한 요소(예: 영상 엔진의 움직임·시간 순서가 원문에 없을 때)만 최소로 채우고 블록 밖에 그렇게 정했다고 밝힌다.

## 4. 바뀌는 매체·입력 모드

- **이미지 → 영상:** 정지 장면의 내용을 첫 상태로 두고 누가 무엇을 어떻게 움직이는지, 카메라와 시간 순서를 [lanes.md](lanes.md) §영상 공통 규칙대로 더한다. 움직임을 사용자가 정하지 않았으면 위 §3의 최소 보충 규칙을 따른다.
- **영상 → 이미지:** 대표 순간 하나를 고르고 움직임·타임코드·소리 지시를 뺀다. 어느 순간을 쓸지가 결과를 가르고 원문에서 정해지지 않으면 그 선택만 묻는다.
- **생성 ↔ 편집 모드:** 새 생성 프롬프트를 편집 모드로 옮길 때는 변경점·보존 조건 형식으로, 편집 프롬프트를 새 생성으로 옮길 때는 완성 장면 서술로 다시 쓴다. 원본 이미지가 대상 입력으로 전달되지 않으면 편집 지시로 바꿀 수 없음을 알린다.

## 5. 납품

- 출력 형식은 [../../SKILL.md](../../SKILL.md) §Output format을 따른다. 대상이 여러 개면 대상마다 자기완결 블록을 하나씩 낸다.
- 블록 밖에는 빠지거나 대체된 조건, 대상이 지원하지 않아 바뀐 값, 가정한 버전·표면만 짧게 적는다. 사소한 문법 치환은 나열하지 않는다. '프롬프트만'·'설명 없이' 요청이면 이 설명도 생략한다. 단, 사용자 요구가 대상에서 지켜지지 않는 경우는 결과를 바꾸므로 한 줄로 알린다.
- 납품 전에 원문과 변환본을 대조해 §2의 내용 층이 모두 남았는지, 원 엔진 문법이 남지 않았는지 확인한다. 실제 생성 결과를 보지 않았으면 같은 결과가 나온다고 말하지 않는다.
