# 이미지 프롬프트 조립 원칙

## 적용 범위

사용자가 MPW 조립 형식, 전문 이미지 레인 또는 기계 인계물을 지정했을 때 쓰는 작성 원칙이다. 일반 이미지 생성과 편집은 [surfaces.md](surfaces.md) §0의 네이티브 경로가 먼저다. 표면별 길이, 비율, 해상도와 품질 설정은 [surfaces.md](surfaces.md)와 [surface-contracts.md](surface-contracts.md)가 소유한다. 조립 결과를 실제 이미지로 생성하는 일은 실행기의 몫이다.

요청에서 피사체, 결과 수, 원본 보존 범위, 글자와 지정 색을 먼저 확인한다. 요청만으로 알 수 없는 정확한 카피나 편집 원본이 결과를 바꾼다면 확인하고, 나머지는 필요한 시각적 선택만 한다. 복잡한 구조가 필요해도 내부 작업표를 그대로 프롬프트에 내보내지 않는다. 독립된 실행 단위마다 필요한 입력과 설정을 함께 인계한다.

## 원칙

### 결과로 쓴다

카메라 장비나 좋다는 평가보다 납품 이미지에서 관찰할 변화를 적는다. 초점이 짧게 떨어져야 한다면 어느 대상 뒤부터 윤곽이 흐려지는지 말하고, 관계 그림이라면 어떤 요소에서 어떤 요소로 선이 이어지는지 적는다. 요구하지 않은 광원과 소재를 장면 전체에 채우지 않는다. 조건이 서로 부딪칠 때만 문단을 나누고, 빈 항목을 만들지 않는다.

### 필요한 수치만

사용자가 준 수량과 치수는 보존한다. 실제 전달 표면이 받는 설정값은 프롬프트 문장과 분리한다([surface-contracts.md](surface-contracts.md) §4). 색은 같은 문서 §4.1의 권한을 따른다. 색명만 지정된 요청에 임의 코드를 브랜드 사양으로 붙이거나, 출처 없는 색 개수와 촬영 비율을 규칙으로 만들지 않는다. 기계 인계 값은 해당 스키마와 검증기의 판정에 맡기며 문서에 허용값 목록을 베끼지 않는다.

### 제공된 피사체와 브랜드 보존

참조 이미지의 역할을 구분한다. 원본 제품을 편집하면 형상, 라벨, 로고와 고유색 중 사용자가 지키라고 한 항목을 명시하고 바꾸는 부분만 좁혀 쓴다. 스타일 참조를 피사체 교체 지시로 오해하지 않는다. 원본에 없는 인물 특징이나 브랜드 장식을 보존 조건처럼 지어내지 않는다. 여러 참조의 결합은 각각 어디에 영향을 주는지 말한다.

### 정확 카피

이미지에서 읽혀야 할 문구는 고쳐 쓸 지시가 아니라 데이터다. 문장부호, 띄어쓰기, 줄바꿈과 혼합 언어를 원문대로 유지하고 따옴표 안에 한 번만 둔다. 문구가 여럿이면 제목, 설명, 제품 라벨처럼 실제 역할과 위치를 구분한다. 지시문에 들어 있는 품질 단어와 따옴표 속 상품명이나 표기 문자를 혼동하지 않는다. 레이아웃과 반복 텍스처의 판정은 [text-structure.md](text-structure.md) §이미지 안의 글자와 §판독 대상과 반복 텍스처를 따른다.

### 후속 조판 경계

수정 가능한 글자층이 납품 조건이면 배경 제작물과 원문 카피, 글꼴과 배치 조건을 조판 단계에 인계한다. 이미지 한 장을 생성해 달라는 요청을 임의로 합성 작업으로 바꾸지는 않는다. 글자가 잘못 그려져도 사용자의 문구를 삭제하거나 짧게 고쳐서는 안 된다. 우선 글자의 역할을 분명히 하고 실제 입력 표면의 크기와 품질 설정, 화면에서 차지하는 영역을 점검한 뒤 편집 또는 모델 변경을 검토한다.

### 피부·재질

실사 질감이 요청됐거나 관측된 실패를 고칠 때만 피부와 소재의 보이는 상태를 쓴다. 원본 사진 편집에 모공, 잔머리, 필름 그레인을 자동 추가하지 않는다. 과매끈한 피부를 포함한 실사 실패의 적용 조건과 처방은 [realism.md](realism.md) §1이 소유한다. 그림자나 반사가 필요한 장면에서는 광원과 접촉 지점이 어긋나지 않는지 확인한다.

### 스타일은 화면 결과로

사조나 필름 이름만으로 결과를 지정했다고 보지 않는다. 실제로 필요한 색의 온도, 대비, 화면 입자, 빛의 방향 가운데 장면을 가르는 차이만 적는다. 사용자가 지정한 매체명은 보존하지만 이름에서 파생된 광원과 색을 묶음으로 강제하지 않는다. 실사 실패 처방도 [realism.md](realism.md) §1에서 해당 증상만 고른다.

### 독립 컷은 따로

각기 다른 결과물을 요구하면 컷별로 실행 가능한 블록을 만든다. 컷마다 핵심 피사체, 보존 조건, 정확 카피가 빠지지 않아야 한다. 한 장 자체가 만화 페이지나 도표라면 그 안의 패널과 연결은 하나의 결과물이다. 여러 독립 이미지를 임의의 격자 한 장으로 바꾸거나 사용자 요청 수량을 늘리지 않는다. 배치 인계와 시리즈 차이 기록은 [production.md](production.md) §인계 경로와 §시리즈 운영을 따른다.

### 제외 조건의 형식

빼고 싶은 사물을 양성 본문 끝에 목록으로 붙이지 않는다. 먼저 남길 장면을 구체화한다. 원본 편집의 변경 금지, 보존, 추가 금지는 필요한 만큼 직접 적어도 된다. 대상 엔진의 인라인 문법이나 별도 제외 필드가 있으면 그 입력으로 보내고, 없으면 원하는 상태와 짧은 자연어 제약을 쓴다. 이 분기의 정본은 [surface-contracts.md](surface-contracts.md) §4다. 렌더 카피 주변의 불필요한 글자를 막을 때도 고정된 금지 문구 묶음 대신 실제 실패에 맞는 한 문장만 쓴다.

### 실행 메타는 본문 밖

모델, 비율, 품질, 출력 경로와 참조 입력 역할은 전달 경로의 설정과 인계 필드로 보낸다. 본문 앞에 실행 설정을 대괄호로 싣거나 마지막에 비율 토큰을 덧붙이지 않는다. 설정 없는 자연어 표면에서 사용자가 요구한 비율은 문장으로 전달할 수 있다. 실행 설정을 별도로 보내더라도 프롬프트와 해당 설정의 주체, 대상 컷이 일치해야 한다.

## 조립 프롬프트 검사

산출 전 [lanes.md](lanes.md) §레인 게이트 카드와 위 원칙으로 결과를 대조한다. S1 기계 계약 산출은 [surface-contracts.md](surface-contracts.md) §1에 따라 `contracts/validate.py`를 실제로 실행한다. 문서 대조만으로 유효한 스키마 산출물이라고 판단하지 않는다. 자연어와 조립 문안의 검사 프로필, 코드 및 사용법은 [production.md](production.md) §검증기와 §검증기 코드를 따른다. 글자 오류나 정보 누락은 실제 결과를 보고 판단한다. 문안 검사는 생성 이미지의 품질을 증명하지 않는다.

## 읽을 자료

표면과 값의 소관은 [surfaces.md](surfaces.md), 설정과 제외 입력은 [surface-contracts.md](surface-contracts.md), 구조 및 텍스트 배치는 [text-structure.md](text-structure.md)를 읽는다. 인물 스틸은 [editorial-fashion.md](editorial-fashion.md), 사진 현실감은 [realism.md](realism.md), 대량 인계는 [production.md](production.md)의 필요한 절만 읽는다. 별도 의류 입력 계약은 [apparel-compiler.md](apparel-compiler.md)를 따른다.
