# 텍스트·구조 이미지 프롬프트 컴파일러

거칠고 모호한 이미지 요청을 이미지 생성 러너(runner)에 넘길 완성 한국어 프로덕션 프롬프트로 바꾼다. 이미지를 직접 생성하지 않는다. 생성·양산 실행은 러너 소관.

**적용 범위:** A/B·Tier·끝 AR는 MPW 컴파일 형식의 계약이다. 일반 모델에 직접 넣는 네이티브 생성·편집 프롬프트에는 이를 강제하지 않는다. 네이티브 작성·검증은 [surfaces.md](surfaces.md) §3.1을 따른다. 아래 S3의 AR 규칙도 컴파일 프로필에 한정한다.

## 2. 철칙 — 절대 어기지 말 것

1. **앞머리 `[AR x:y SIZE wxh]` 브래킷 금지.** 비율·size는 실행 파라미터로만 둔다. **S3 붙여넣기 표면에서만** 끝에 `AR x:y` 토큰 하나를 둔다 — S1·S2에서는 비율도 파라미터이므로 본문에 AR을 쓰지 않는다(§5). 슬롯 토큰 `[PERSONA_LOCK]`류는 **작성 단계 전용**이다. 최종 프롬프트에 브래킷이 잔존하면 실격이다.
2. **컴파일 프로필의 긍정형 기본값 + 화이트리스트 2종.** 아래 티어는 MPW 형식 호환 정책이며 모든 이미지 모델의 자연어 능력에 관한 규칙이 아니다. 네이티브 모델의 배제·보존 지시는 [surfaces.md](surfaces.md) §4를 따른다. 컴파일 Tier-0에서는 군중 배제를 "프레임 안엔 인물 한 명, 단독", 배경 배제를 "깨끗한 단색 배경"처럼 쓴다. 워터마크 추가 금지를 브랜드 제거로 바꾸지 않으며 제공된 상품 로고·문구는 보존한다. 실패 축별 긍정형 재서술 사전은 [editorial/photo-vocab.md](editorial/photo-vocab.md) §7.9다.

   | 티어 | 조건 | 허용 문구 |
   |---|---|---|
   | **Tier-0 기본** | 항상 | all-positive. 부정문 0개 |
   | **Tier-1 텍스트 렌더 가드** | 렌더 텍스트(따옴표 카피)가 실제로 있을 때만 | 화이트리스트 7종: `no extra words` · `no duplicate text` · `no invented glyphs` · `no watermark` · `no logo` · `no extra text` · `verbatim, no extra characters` |
   | **Tier-2 화보 컴플라이언스 레인** | 명시 선언 시만. 휴리스틱 승격 금지 | SAFETY_ASSERT(긍정형, 피사체절) + NEGATIVE_TAIL(AR 직전 정확히 1회) **페어** — 고정 문자열, 상세는 화보 레퍼런스 |

   Tier-1 기본 가드는 `지정 문구만 한 번씩 또렷하게.`처럼 짧게 쓴다. 반복·유령 글자 등 실제 실패를 교정할 때 필요한 화이트리스트만 추가한다. 전체 결합형은 선택 사항이다: `All text appears once, perfectly legible — no duplicate text, no extra words, no invented glyphs, no watermark.`

   Tier-2 고정 문자열 — SAFETY_ASSERT: `adult subject, non-nude fashion editorial, fully opaque clothing, secure garment coverage, non-sexual presentation` / NEGATIVE_TAIL: `no nudity, no nipple or genital exposure, no wardrobe malfunction, no extra people, no text, no watermark` (순서 보존 부분집합만 허용, tail 단독 사용 금지). **정본: [editorial/tier2-safety.md](editorial/tier2-safety.md) §2 코드블록** — 이 줄은 인라인 복사본이며, `scripts/lint.py`가 정본·이 복사본·검증기 상수를 byte 대조한다.

   | 빼려는 것 | 레인 |
   |---|---|
   | 장면 요소(사람·사물·배경·소품) | **긍정형 재서술** (Tier-0) |
   | 텍스트 렌더 결함(중복·유령 글자·워터마크) | **Tier-1** 화이트리스트 |
   | 정책 안전 단언(화보) | **Tier-2** 페어 |

   `Negative:` 라벨 섹션은 **전 티어 금지**다.
3. **저신호 어휘를 결과로 환원한다.** `masterpiece/best quality/8k/4k/uhd/trending on artstation/ultra-detailed/highly detailed/sharp focus`는 최신 모델에서 해롭다기보다 **아무것도 정하지 못한다** — 화면 결과를 대신하는 자리에 두는 것이 금지이고, 결과 서술이 이미 있으면 굳이 넣을 이유도 없다. 반면 아래는 실제로 깨지므로 그대로 금지다: 가중치 `(word:1.3)`, 슬래시 플래그 `--ar/--v`(다른 엔진 문법), 본문 `§`. 빈 형용사 `멋지게/감성적으로/고급스럽게/세련되게/beautiful/stunning`, **무대 지정도 동급 노이즈**다. "어워드 수준으로/전문가처럼/최고급"은 기준이 프롬프트 밖에 있어 평균값만 나온다. 이미 장면이 명확하면 지우고, 빠진 시각 조건이 있을 때만 구체화한다. 수치·예시를 채우려고 새 요구를 만들지 않는다.
4. **장비 스펙은 노이즈 → 결과로 환원.** 카메라 EXIF·조명 장비명 대신 결과를 쓴다. 예: `shallow DoF, background falls off softly`, `long soft-edged shadows`, `warm key + cool rim`. 패션의 `Lens character:`·`Director signature:` 라인은 결과+레퍼런스 앵커라 예외다.
5. **수치는 필요한 축에만 쓴다.** 사용자 지정 색·수량·배치와 전문 레인의 명시 계약은 보존한다. 일반 컷에 HEX 개수·켈빈·광량비·카메라 거리를 새로 만들지 않는다. 색이 결과를 가르면 HEX도 짧은 완결본에 유지하고 [surfaces.md](surfaces.md) §4.1의 색상 계약을 따른다. 색 이름이나 원본 색 보존으로 충분한 요청은 그대로 쓴다. `key:fill`을 실제로 쓸 때의 표기는 [editorial/photo-vocab.md](editorial/photo-vocab.md) §7.2가 정본이다.
6. **1행 = 1컷 = 1호출.** **독립 컷 여러 개**를 한 캔버스에 묶는 그리드/매트릭스 금지. 산출물 자체가 표·패널·슬라이드·도감·만화 페이지면 내부 그리드는 허용 — 1행=1컷=1호출 원칙은 독립 결과물 단위에만 적용. 여러 컷은 N개 별도 행으로 분리한다.
7. **피부·재질은 요청에 맞게 쓴다.** 실사 질감이 필요한 경우 `natural skin texture`처럼 보이는 결과를 간단히 지정한다. 원본 편집에 모공·그레인·잔머리를 자동으로 추가하지 않는다. 조건부 현실감 검사는 [realism.md](realism.md) §3을 따른다.
8. **제공된 피사체와 브랜드 정보를 보존한다.** 사용자가 제공한 인물·상품·로고를 임의로 바꾸지 않는다. 새 브랜드/페르소나가 필요하지만 지정되지 않았으면 가상으로 작성한다.
9. **이미지 안에서 렌더할 텍스트는 정확 카피로 고정한다.** 기본은 따옴표 카피와 필요한 롤 라벨로 생성하는 방식이다. 글자가 틀리면 지정 카피를 유지한 채 타이포·레이아웃, 지원되는 부분 편집·재생성·해상도/품질 레버 또는 텍스트 특화 모델을 조정한다. 사용자가 텍스트 합성·편집 가능한 문자 레이어를 요청했으면 배경 생성과 조판을 나눈 후속 제작 계약으로 작성한다. 생성만 요청한 작업을 몰래 합성으로 대체하지 않는다. 카피 축소는 작성자가 만든 조절 가능한 문구에만 적용하며, 사용자 지정 문구·정보량·출력 수는 보존한다.
10. **스타일은 결정적인 화면 결과로 쓴다.** 모호한 룩·무드에는 `따뜻한 색감과 낮은 대비`처럼 구별되는 특성만 덧붙인다. 필름명·광원·노출·색감·그레인·분위기를 한 세트로 채우지 않는다. 사용자 지정 필름명은 유지하며 필요할 때만 [editorial/photo-vocab.md](editorial/photo-vocab.md) §7.4를 참조한다.

### 발전: 철칙 위반 증상 → 원인 역추적 표

| 증상 | 원인 | 고치는 문장 |
|---|---|---|
| 배제한 물체가 오히려 등장 | 제외 명사가 일반 프롬프트에 섞였거나 제약이 반영되지 않음 | 원하는 상태로 좁히고, 네이티브 모델은 실제 배제 입력 형식도 확인한다 |
| 카피가 두 번 렌더됨 | 같은 따옴표 카피를 본문과 Text-in-image에 중복 배치 | 카피는 롤 라벨 블록 1곳에만 둔다 |
| 앞머리 메타가 이미지 안에 찍힘 | `[AR ...]` 또는 슬롯 토큰이 최종 프롬프트에 잔존 | 메타는 실행 파라미터로 뺀다. S3면 끝 `AR x:y` 하나만 남기고, S1·S2면 본문에서 AR도 없앤다 |
| 피부가 플라스틱처럼 보임 | 미화 형용사로 피부를 지시 | `natural skin texture, visible pores, subtle film grain` |
| 조명이 장비 카탈로그처럼 산만함 | 장비명·EXIF를 나열 | `warm key + cool rim`, `long soft-edged shadows`처럼 결과를 쓴다 |
| 필름명·감성 라벨을 썼는데 룩 차이가 안 남 | 이름을 단독 명사로 뒀다 — 결과 병기 누락 | `[이름] + [화면 결과]`로 병기: `Gold 200-look, warm golden tones, retro feeling` |
| 복잡한 도표가 빈 카드 4개로 단순화 | 밀도·노드·연결·좌표를 생략 | 섹션 수, 노드 좌표, 화살표 출발→도착, 라벨을 문장으로 고정한다 |

## 3. 기본 작성 — 짧은 장면 또는 편집 지시

**생성:** 피사체와 행동/배치를 먼저 쓰고, 결과를 구별하는 스타일·빛·색·재질만 이어 쓴다. **편집:** 입력의 역할, 바꿀 부분, 보존 조건, 출력 조건만 쓴다. 보이는 원본 전체를 재묘사하지 않는다. 길이·확장 기준은 [surfaces.md](surfaces.md) §0-2가 정본이다.

단순 예: `흰 배경 중앙에 빨간 원 하나를 배치한 평면 아이콘. AR 1:1`

복잡한 컷에는 필요한 라벨만 골라 쓴다. Scene은 장면·관계, Camera는 시점·프레이밍, Lighting은 필요한 빛, Color grading은 지정 색감, Texture/Medium은 표현 매체, Text-in-image는 정확 카피·위치를 구분하는 선택 도구다. 어느 라벨도 최소 분량을 채우는 슬롯이 아니다. S3만 끝에 AR을 두고 S1·S2는 파라미터로 넘긴다(§5).

이미지 편집·배치의 보존 계약은 [lanes.md](lanes.md) §편집·제품 배치 압축을 따른다.

## 4. 포맷 A / 포맷 B 라우팅

| 포맷 | 대상 | 형태 | 판정 문장 |
|---|---|---|---|
| **포맷 A — 일반 이미지** | 포스터·아이콘·제품·도해·만화 등 | 짧은 자연어 기본, 복잡할 때만 라벨 | 구조가 필요하다는 이유로 조명·질감을 의무화하지 않는다. |
| **포맷 B — 인물 화보** | 단독 인물 화보/에디토리얼 | 짧은 한 문단 | 요청한 인물·표정·포즈·의상이 핵심이다. |

포맷 A/B는 기존 레코드와의 호환용 분류다. 인물 요청에 없는 얼굴·헤어·장르앵커·팔레트를 채우지 않는다. Tier-2가 명시됐을 때만 동결 assert/tail 페어를 유지한다. 포맷만으로 길이·색 개수·촬영 슬롯을 요구하지 않는다.

기본 세로 비율도 표면이 정한다(§5).

| 표면 | 포맷 B 기본 |
|---|---|
| **S3 붙여넣기** | 끝 토큰 `AR 2:3` — 세로 화보 표준 |
| **S1-legacy 벌크(jsonl)** | `ar: 2:3` + `production.md` §11 매핑의 `1024x1536` |
| **S1 기계 계약** | `2:3`은 스키마 `ar` enum에 **없다**. enum 안의 세로 비율(`3:4`)을 고르고 `size`는 `contracts/validate.py`의 `GEOMETRY` 매핑을 그대로 따른다. `2:3`·`1024x1536`을 이 경로에 옮겨 적으면 `production_geometry_mismatch`로 거부된다 |
| **S2 플랫폼** | 현재 모델 상세 조회 도구와 호출 스키마의 비율·해상도 정의를 따른다 |

## 5. 해상도·비율 — 표면이 정한다

**정본은 [surfaces.md](surfaces.md)다.** 표면을 판정하지 않고 픽셀값을 쓰면 하류에서 거부된다.

| 표면 | 무엇을 쓰나 | 정본 |
|---|---|---|
| **S1 기계 계약** | `ar` + `size` + `quality`, 값은 **스키마 enum이 전부** | `contracts/v1/*.schema.json`, 매핑은 `contracts/validate.py`의 `GEOMETRY` |
| **S2 플랫폼 파라미터** | 모델별 `aspect_ratio`·`resolution`/`quality`·픽셀 필드 정의를 확인. 없는 축은 만들지 않음 | 현재 모델 상세 조회 도구와 실제 호출 스키마 |
| **S3 붙여넣기** | 끝에 `AR x:y` 토큰 하나. 픽셀·품질은 사용자가 UI에서 고름 | — |

- **S1에서 스키마 밖 값을 쓰지 않는다.** 문서 어딘가에서 본 비율·픽셀값이 스키마 enum에 없으면 그 값은 쓸 수 없고, 쓰면 `production_geometry_mismatch`로 거부된다. 컴파일 전 `python3 contracts/validate.py`로 실제 검증한다.
- **`auto` 금지는 S1 한정 규칙이다.** S2에서는 `auto`가 여러 모델의 유효한 `aspect_ratios` 값이며 `image_auto` 모델도 있다.
- 챕터 안에서는 해상도 축을 통일한다(S1은 size, S2는 resolution 티어).
- **투명 배경은 선택한 표면의 지원에 따른다.** 직접 알파 출력을 지원하면 그 기능을 쓰고, 지원하지 않는 기계 계약·플랫폼에서는 단색 배경 생성 후 컷아웃을 명시한다([surfaces.md](surfaces.md) §5). API 기능을 S1 스키마에 임의로 이식하지 않는다.

### 레거시 벌크 경로 (S1-legacy)

`production.md` §2의 `prompts.jsonl` 6-size 벌크 스키마는 기계 계약(`ar` 5종·`size` 3종)보다 넓다. **두 경로는 같지 않다.** 신규 컴파일은 기계 계약을 따르고, jsonl 벌크는 기존 배치를 읽을 때만 쓴다. 둘을 섞은 값(예: 기계 계약 경로에 `2048x2048`)은 어느 쪽에서도 유효하지 않다.

## 6. 텍스트 렌더 규칙 — 한글 포함

따옴표 안의 정확 카피는 렌더할 데이터다. `NO FEAR`·`4K` 같은 문구를 지시문용 네거티브·품질태그로 오판해 바꾸지 않는다. 지시문 어휘 검사와 카피의 정확성·중복 검사는 구분한다.

| 규칙 | 작성법 | 판정 문장 |
|---|---|---|
| 정확 카피 고정 | `text reads "오늘 더 따뜻해요"`. 필요한 위치·위계만 추가 | 따옴표 밖에 핵심 카피가 떠돌면 틀렸고, 정확 카피가 따옴표 안에 1회 있으면 맞다. |
| 롤 라벨 분리 | `headline "봄밤 야시장"` / `subhead "4.20 SAT 6PM"` / `callout "선착순 100명"` | 카피 2개 이상이 한 덩어리면 틀렸고, 롤마다 위치·크기·폰트가 있으면 맞다. |
| KO/EN 언어 라벨 | 새 카피를 설계할 때만 읽기 쉬운 줄·롤 분리를 고려한다 | 사용자가 지정한 혼합 문구는 그대로 보존한다. |
| Tier-1 결합 | 렌더 텍스트가 있으면 §2의 짧은 가드 1회 | 같은 카피를 반복하지 않고, 필요한 가드만 한 번 쓴다. |
| 한글 스펠아웃 금지 | 하이픈 풀어쓰기 금지. 하이픈은 글자로 렌더됨(실측) | 한글을 음절 단위로 쪼개면 틀렸고, 실제 문구를 그대로 쓰면 맞다. |
| 정확도 레버 | **글자에 주어지는 픽셀 높이**. 표면별 레버와 허용값은 [surfaces.md](surfaces.md)가 정한다. S1은 스키마가 제공하는 size·quality 축, S2는 선택 모델 런타임이 실제로 제공하는 resolution·quality·mode 축에서 올리고, 그래도 안 되면 텍스트 특화 모델로 교체([model-routing.md](model-routing.md)). 없는 축이나 값을 만들지 않는다. 영문 조어만 ALL CAPS/스펠아웃 최후수단 | 모델 탓으로 끝내면 틀렸고, 표면이 제공하는 해상도·카피 수·롤 라벨·모델을 조절하면 맞다. |
| 밀집 텍스트 | 카피 블록 3개+ 또는 소형 글자는 품질 최상단 + 해상도 상향을 함께 건다. 캔버스가 커질수록 한글 정확도가 올라간다(실측) | 작은 캔버스에 밀어 넣으면 틀렸고, 해상도로 글자 높이를 확보하면 맞다. |
| 플레이스홀더 금지 | 렌더 라벨엔 실제 문구만 둔다 | "제목 입력" 같은 대체 문구가 보이면 틀렸고, 최종 카피가 보이면 맞다. |

## 7. 국문/영문 혼용 규칙

| 위치 | 우선 언어 | 예시 |
