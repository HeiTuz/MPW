# IMAGE·COMPOSITE·영상 라우트에서만 로드

## 0. 선행 판정 — 표면부터 정한다

**[surfaces.md](surfaces.md)를 먼저 읽는다.** 산출물이 기계 계약(S1)·플랫폼 파라미터(S2)·붙여넣기 UI(S3) 중 어디로 나가는지에 따라 길이·비율·해상도 계약이 통째로 달라진다. 이 파일의 레인 규칙은 그 위에 얹힌다.

- 파라미터로 표현되는 축(비율·해상도·품질·길이·오디오·팔레트·프리셋)은 **산문에 중복 기술하지 않는다**([surfaces.md](surfaces.md) §4).
- 사이즈·길이 문장이 [surfaces.md](surfaces.md)와 충돌하면 surfaces.md가 이긴다.

**"모델의 `aspect_ratios` 안에서"의 예외 — 빈 배열:** 일반 `aspect_ratio`를 만들지 않고 모델별 대체 필드를 확인한다. 예를 들어 `clipify`는 `clip_aspect`를 쓴다. 대체 필드도 없을 때만 입력 이미지·모델 기본값을 따르며, 빈 배열만으로 게이트 실패로 처리하지 않는다. 정본은 [surfaces.md](surfaces.md) §2다.

실사 서브레인은 [realism.md](realism.md) §3의 조건부 현실감 검사를 적용한다. 광원·렌즈·불완전성 목록을 모든 프롬프트에 추가하지 않는다. 영상 전용 검사는 같은 파일 §6이다.

## 엔진 라우팅

**모델 후보 결정의 정본은 [model-routing.md](model-routing.md)다.** 목적축(정확 텍스트·벡터 로고·인물 사실감·동일 인물·지시 편집·초고해상·프롬프트 준수·제품 광고·영상 각 축)에서 **모델 id와 입력 모드까지** 정한다. 플랫폼 이름만으로 지원 기능을 단정하지 않는다.

여기서는 레인만 가른다.

| 요청 신호 | 레인 |
|---|---|
| 정확한 텍스트 렌더, 포스터, 카드뉴스, 인포그래픽, 제품 도감, 타이포 포스터, 레이아웃·브랜딩 목업·아이콘·만화 | **텍스트·구조 이미지** — 네이티브 자연어 기본. MPW 형식·전문 패턴 지정 시 [compiler.md](compiler.md), TP 라우팅 [typography-poster-router.md](typography-poster-router.md) |
| 인물 사실감, 패션 스틸, 동일 인물, 카메라 모션 | **인물·사실감 이미지** / **영상** |
| 원본 피사체 보존과 배경 교체 | **COMPOSITE** |

표면과 모델이 명시되면 따른다. 한 컷에 여러 목적이 있으면 하나의 결과물에 대한 요구로 유지한다. 지원 여부를 확인하고 같은 결과를 낼 모델·편집 경로를 고르며, 목적 수만으로 출력 장수를 늘리지 않는다. 룩·조명·기법은 필요한 화면 결과로 쓴다. 한국 로컬리티는 관찰 가능한 공간·의상·조명 단서로 쓰며 국적에서 외형을 추론하지 않는다. 안전 매트릭스는 [editorial/tier2-safety.md](editorial/tier2-safety.md) §13이다.

## 텍스트·구조 이미지 레인

단순 생성·편집은 짧은 자연어로 완성한다. MPW 컴파일 형식이 필요할 때만 [compiler.md](compiler.md)의 A/B·Tier를 적용한다. 복잡한 구성에도 필요한 라벨만 추가한다.

- 결과 상태를 우선 쓰고, 변경 범위·보존 조건이 분명해지는 짧은 제약은 남긴다.
- 명시된 컴파일 형식의 Tier 정책·토큰·결합 공식은 [compiler.md](compiler.md) §2가 정본이다.
- 제공된 인물·상표의 보존은 [compiler.md](compiler.md) 철칙 8을 따른다.
- 여러 독립 컷은 한 캔버스에 묶지 않는다. 한 줄은 한 컷·한 호출이다.
- S3는 경로 참조와 오버플로우 문서를 금지한다. 길이를 줄여도 상한을 넘으면 전달 경로를 조정한다. 요청한 한 컷을 임의로 분리하지 않는다.
- 제품·캠페인은 요청한 상품과 카피가 정확히 읽히게 한다. 반사·그림자·소품은 해당 연출을 원할 때만 넣는다. 흰 배경·무그림자·원본 보존 요청에 이를 자동 추가하지 않는다.
- 팔레트 파라미터(`colors[]`·`background_color`)를 가진 모델에서는 HEX를 본문에 반복하지 않고 파라미터로 넘긴다.
- 벡터·SVG 계열 자산은 실제 벡터 출력을 지원하는 경로를 확인한다([model-routing.md](model-routing.md)). 지정 모델이 이를 지원하지 않으면 형식 충돌과 필요한 대안을 설명한다.

정밀 컴파일의 정본은 [compiler.md](compiler.md), 카테고리는 [categories.md](categories.md), 패션은 [editorial-fashion.md](editorial-fashion.md), 룩은 [look-and-concept.md](look-and-concept.md), 타이포는 [typography.md](typography.md), 양산은 [production.md](production.md)이다.

### 편집·제품 배치 압축

변경점과 보존 조건을 묶어 쓴다. 원본의 형태·색·재질·로고/문구·구도 중 유지할 축을 구체화하고, 참조 이미지가 이미 전달하는 외형 설명은 반복하지 않는다. 디테일 컷은 보이는 범위를 유지하며 보이지 않는 부분을 새로 만들지 않는다.

**독립 원본들을 일괄 편집하는 요청**에서는 업로드 순서대로 입력 한 장당 별도 결과 한 장을 만든다. 편집 대상·배경·스타일 참조를 함께 쓰는 요청의 결과 수는 사용자 계약을 따르며, 참조 한 장마다 결과를 만들지 않는다. 한 호출의 공통 지시는 한 번만 쓰고, 호출을 나누면 각 블록에 필요한 보존 조건을 포함한다. 정사각형 확장이 요청되면 배경만 확장한다. 결과 수·비율·보존 조건은 압축해도 남긴다.

## 인물·사실감 이미지 레인

<!-- 구 §Higgsfield 레인 — 2026-07-25 개명. 다른 파일의 옛 이름 참조는 이 절을 가리킨다. -->

프레이밍, 인물 아이덴티티, 모션의 요구를 구분하되 요청한 결과물 안에 유지한다. 모델 후보는 [model-routing.md](model-routing.md)에서 고른다.

**Soul 계열(`soul_2`/`soul_v2`/`soul_cinematic`) 프롬프트 설계 정본은 [soul-v2-director.md](soul-v2-director.md)다**: 필요한 시각 조건을 한 문단에 쓰고 해당 문서의 참조 순서·지시 우선순위·앵커 한도를 따른다. **4레이어 참조 순서는 Soul 전용이다** — 슬롯을 모두 채우거나 다른 모델로 그대로 복사하지 않는다.

- 동일 인물은 현재 모델과 실제 호출 도구가 지원하는 참조·Element·기존 정체성 ID 중 적합한 경로를 쓴다. `soul_id`나 훈련 절차가 모든 표면에 있다고 가정하지 않으며, 텍스트 묘사만으로 동일 인물을 보존했다고 주장하지 않는다.
- 비율·품질은 파라미터다(`quality: 1.5k/2k` 등). 본문에 쓰지 않는다.
- 전역 색감은 레퍼런스로 전달할 수 있다. 실제 도구의 미디어 롤로 연결하고, 어느 이미지에서 색감만 가져오는지 짧게 지정한다. 참조의 피사체까지 복제하지 않는다.
- **프리셋을 스틸의 필수 요소로 두지 않는다.** MCP 로스터에서 `preset_id` 파라미터를 갖는 것은 영상 경로뿐이다(2026-07-25 확인) — 이미지 모델 중 이 파라미터를 가진 것은 없다. 웹 UI에 스타일 프리셋이 보인다면 그건 UI 라벨이며 프롬프트 본문에 쓰는 값이 아니다.
- 정확 카피가 함께 필요하면 같은 컷의 요구로 유지하고 해당 모델의 텍스트·편집 지원을 확인한다. 별도 컷은 사용자 출력 계약이 허용할 때만 만든다.

### 얼굴 참조 민감도 오탐 대응

얼굴 참조 입력에서 `Output may contain sensitive content`가 돌아오면 프롬프트를 장황하게 순화하지 않는다. `identity`, `blend`, `synthesize`, `four reference faces`, `ID-photo`, `morph`, 상세 얼굴 해부학처럼 얼굴조작으로 읽히는 메타 설명을 제거하고, 결과 화면·각도·렌즈·조명만 짧게 쓴다. 참조 이미지는 미디어 슬롯이 전달하므로 프롬프트에서 다시 설명하지 않는다. 한 장의 AI 생성 참조로도 같은 오류가 나면 입력 얼굴 자체의 분류 오탐 가능성이 높다. 이때 재인코딩·메타데이터 삭제·얼굴 크롭을 반복하지 말고 다른 참조 컷이나 다른 모델을 사용한다. 3×3 캐릭터 시트는 `character-development sheet`·패널별 각도·일관된 촬영 조건으로 기술하며 다른 엔진의 URL/플래그를 섞지 않는다.

**같은 원칙이 Tier-2 화보 레인에도 적용된다**([compiler.md](compiler.md) §2): 신체·연령 메타 서술을 길게 덧붙이는 것은 분류기 오탐을 줄이는 게 아니라 늘릴 수 있다. 고정 문자열을 반사적으로 붙이지 말고 해당 레인이 명시 선언됐을 때만 쓴다.

## 배경 합성 레인 (COMPOSITE)

첫 문장에 배경 교체 작업과 원본 보존 범위를 쓴다. 원본의 캔버스·피사체 기하는 고정한다. 피사체 톤 변경을 허용하지 않았으면 재조명 A를 사용한다. 픽셀 불변 요청은 프롬프트만으로 보증하지 않으며, 원본 피사체를 재합성하는 등 해당 보존을 지원하는 실행 방법이 필요하다.

1. **프레임 락**: 입력과 같은 크기·비율, 크롭·줌·팬·재중앙·여백 재배분 금지.
2. **피사체 락**: 리샘플·워핑·포즈 재구성·실루엣 변경 금지.
3. **정체성·의상 보호**: 기하·자연 비대칭·피부 질감·직물 패턴을 보존한다.
4. **배경 규칙**: 신규 외부 배경만 생성하고, 원근은 카메라 지오메트리 또는 수동 정합 중 하나로 맞춘다.
5. **재조명 다이얼**: A 피사체 픽셀 무접촉 / B 형태·재질·고유색을 유지하는 미세 톤 정합 / C 피사체 재조명 허용 중 하나를 명시한다. 사용자 수치가 있으면 보존하고, 검증할 수 없는 허용치를 새로 만들지 않는다.
6. **통합**: 배경의 원근·광원·경계를 원본에 맞춘다. 필요한 경우 배경 쪽 접지 그림자를 조정하며, 원본 피사체에 그레인·광원·질감을 자동 추가하지 않는다.
7. **판정·실패**: 동일인 인식이 미적 개선보다 우선이며, 피사체 이동·캔버스 변경·얼굴 재드로잉·직물 변형·원근 불일치·떠 있는 발은 실패로 처리한다.

연산 금지는 이 레인에서 필요한 계약이다. 장면 내용은 긍정형으로 쓴다. 긴 불리언 스택은 캐노니컬 문장으로 병합하고, 픽셀 고정 지원 여부가 불명확한 엔진은 확인 노트를 남긴다.

### 압축 규칙

긴 `SYSTEM OVERRIDE` 헤더나 반복되는 절대 금지 조항을 프롬프트에 복사하지 않는다. 다음 5단계로 압축한다:

1. 한 가지 작업 선언 (배경 합성, 픽셀 고정)
2. 캔버스/피사체/정체성/의상 락
3. 제한된 톤/조명 통합
4. 배경 위치 단서 팩
5. 짧은 실패 조항

### 적격 키워드

규칙 1~7에서 다루지 않는 추가 제약들을 간결히 지정:

- **recognition over beauty**: 미화보다 동일인 인식을 우선. 얼굴 평균화·대칭 보정·피부 스무딩 금지.
- **background clipping allowance**: 배경 오브제를 살리려 카메라를 움직이지 않는다. 잠긴 프레임 밖 요소는 잘림.
- **passive perspective match**: 카메라 재추정/보정 없이 기존 사진 시점에 배경 깊이만 정합.
- **environment cue pack**: 장소를 로고·간판 아닌 재료·시간·빛·필수 구조물로 정의.

### Compact clause template

```text
배경만 원본 광원과 어울리는 로케이션으로 교체한다. 원본 캔버스·크롭·피사체 위치와 크기·포즈·얼굴·표정·머리카락·의상 색/패턴/질감을 보존한다. 재조명 A: 피사체는 수정하지 않고 배경의 원근·빛·경계를 원본과 맞춘다. 얼굴·의상·프레임이 바뀌면 실패다.
```

## 영상 공통 규칙

단일 클립은 요청한 움직임과 필요한 오디오를 짧게 쓴다. 정지 카메라 요청에 카메라 모션을 추가하지 않는다. 시간 순서나 샷 전환이 중요한 경우에만 스토리보드로 나누고, 각 클립의 행동을 실행 가능한 범위로 정리한다. SFX·앰비언스는 필요할 때만 넣는다.

대사의 원문과 언어는 보존하되 엔진별 형식을 따른다. **Veo는 따옴표가 화면 자막으로 읽힐 수 있어** `The speaker says in Korean: 안녕하세요.`처럼 쓴다. Veo 3.1의 장면 프롬프트 지원 언어는 영어이며, 발화 언어와 구분한다. 이를 모든 영상 모델의 영어·따옴표 의무로 일반화하지 않는다. 출처는 [surfaces.md](surfaces.md) §7이다.

**파라미터로 되는 것은 프롬프트에 쓰지 않는다**([surfaces.md](surfaces.md) §4). 아래는 해당 파라미터가 실제 제공될 때의 대응 예다. 필드가 없는 모델에 임의 파라미터를 만들지 않는다. 그런 표면에서 지원하는 카메라·속도·소리 요청은 자연어로 전달한다.

| 산문에 쓰기 쉬운 것 | 실제 파라미터 |
|---|---|
| "5초 클립으로" | `duration` — **모델별 열거값 또는 범위**. 스토리보드 씬 길이를 여기에 맞춘다 |
| "슬로우모션으로" | `speedramp` / `slow_motion` |
| "느와르 톤으로" | `genre` — **옵션 목록이 모델마다 다르다.** 예: `cinematic_studio_video_v2`엔 `noir`가 아예 없고 `cinematic_studio_3_0`엔 있다(2026-07-25 런타임 확인). 특정 목록을 외워 쓰지 말고 그 모델의 enum을 확인한다 |
| "무음으로" / "소리 넣어줘" | `generate_audio` / `sound` |
| "1080p로" | `resolution` / `mode` / `quality` |
| "지시를 정확히 따라라" | `cfg_scale` |
| "컷이 세 번 바뀌고…" | `multi_shots` + `multi_prompt` |
| "이 이미지로 시작해서 저 이미지로 끝나게" | `start_image` / `end_image` 미디어 롤 |

배제 조건은 [surfaces.md](surfaces.md) §4에 따라 보낸다. Veo의 제외 명사 목록은 별도 `negativePrompt` 입력란용이며 일반 프롬프트에 섞지 않는다. 별도 필드가 없는 표면에서는 원하는 상태와 필요한 짧은 제약으로 쓴다. ModelArk direct Seedance 2.0의 세부 규칙은 [seedance-2.md](seedance-2.md)를 따르며, Higgsfield나 2.5에 자동 상속하지 않는다.

image-to-video에서는 시작 이미지의 외형 전체를 반복하지 않고 변화·동작·필요한 오디오를 쓴다. 핵심 보존 조건은 남긴다. 정체성·스타일 레퍼런스는 시작 프레임과 다른 입력 역할이므로 실제 모드가 허용하는 조합인지 확인한다. 기하 보존 요청은 원본 비율을 유지한다. Grok의 모드별 작성법은 [grok-imagine.md](grok-imagine.md), 입력 조합·설정은 [surfaces.md](surfaces.md) §4.2를 따른다.
